# 合肥大学通知监测器

自动盯合肥大学官网，把**研究生事务、奖学金与资助、竞赛与创新创业**相关的新通知整理成日报，
有新通知时自动开一条 GitHub Issue，GitHub 会给仓库主人发邮件提醒；没有新通知则不打扰。

## 它怎么工作

```
每天 08:00 / 20:00（北京时间）
        ↓
抓取 14 个官网栏目（每栏目 2 页）
        ↓
标题关键词筛选 + 排除招标采购等无关内容
        ↓
与 state/seen.json 比对去重
        ↓
生成 Markdown 日报 → reports/
        ↓
有新增 → 创建 GitHub Issue（触发邮件提醒）
```

## 监测栏目

| 类别 | 栏目 |
| --- | --- |
| 研究生院 | 通知公告、公示公告、研招通知、学生工作通知、规章制度、首页 |
| 生命健康与环境工程学院 | 通知公告、首页 |
| 创新创业学院 | 赛事发布、首页 |
| 校团委 | 首页 |
| 教务处 | 相关通知、首页 |
| 学校 | 信息公开网首页 |

栏目清单在 `monitor.py` 顶部的 `SOURCES`，关键词在 `TOPICS`，屏蔽词在 `EXCLUDE`。
想加栏目：往 `SOURCES` 里加一行 `(名称, URL, "all"或"filter", 默认分类)` 即可。

- `all`：整栏都算目标内容（如研究生院通知公告）
- `filter`：只有标题命中关键词才收录（如学院首页，避免混入无关新闻）

## 运行时间

工作流 `.github/workflows/monitor.yml` 用 UTC cron：

| cron | 北京时间 |
| --- | --- |
| `0 0 * * *` | 每天 08:00 |
| `0 12 * * *` | 每天 20:00 |

> GitHub Actions 的定时任务可能有几分钟到几十分钟的排队延迟，属于正常现象。

## 首次运行说明

第一次运行时 `state/seen.json` 不存在，程序会把当前所有在榜通知记为**基线**并存档，
**不推送**，避免一次性收到几十条历史通知。从第二次运行起，只提醒新增内容。

想强制重建基线：Actions → 手动 `Run workflow`，把 `init` 填 `true`。

## 怎么收到提醒

1. 在仓库右上角点 **Watch**（自己创建的仓库默认已订阅，确认不是 "Not watching"）。
2. GitHub → Settings → Notifications，勾选 **Email** 并确认 "Issues" 相关通知开启。
3. 之后每次有新通知，Actions 会以 `github-actions[bot]` 身份创建 Issue，标题形如
   `[合大通知速递] 11-10 08:00 新增 3 条（奖学金与资助 1 / 竞赛与创新创业 2）`，
   邮件会发到你的 GitHub 绑定邮箱。

日报全文同时存在 `reports/`，`reports/latest.md` 永远是最新一次。

## 本地运行

```bash
pip install -r requirements.txt
python monitor.py --dry-run     # 试跑，只打印，不写文件不推送
python monitor.py               # 正式跑一次（本地无 GITHUB_TOKEN 时会跳过 Issue 推送）
```

可选参数：`--pages 3`（多抓一页）、`--no-summary`（不抓正文摘要）、`--init`（重建基线）。

## 几点注意

- 只抓取学校官网**公开**的通知列表页，频率低（每天 2 次）、单页间隔 0.3 秒，不对站点造成压力。
- 官网使用 Webplus 建站系统，列表页为 `list.htm` / `list2.htm`，详情页为 `page.htm`。
  若学校改版导致解析失效，改 `parse_list()` 里的选择器即可。
- 响应头未声明 charset，代码里强制按 UTF-8 解码；本地运行时默认忽略系统代理（`HFUU_TRUST_ENV=1` 可开启）。
- 公开仓库若连续 60 天没有任何提交活动，GitHub 会自动暂停定时任务；随便改点东西提交一次即可恢复
  （本工作流每次有新通知都会提交日报，正常不会触发）。
- 若无新增通知，工作流仍会运行，但不会创建 Issue、也不会刷屏。
